# Cortex backend setup checklist

Everything needed to stand up (or update) the Cortex backend, in order. Secrets
(`service_role` key, Apple `.p8`, SMTP password) are **never** committed — see
[`SECURITY.md`](../SECURITY.md).

---

## 1. Database — run the SQL

**Easiest:** run the single bundle **[`setup_all.sql`](setup_all.sql)** in the
Supabase SQL editor. It's idempotent (safe to re-run after app updates) and
includes everything below in the right order.

Or run the individual files **in this order**:

| # | File | What it adds |
|---|------|--------------|
| 1 | [`schema.sql`](schema.sql) | Core tables (`devices`, `content`, `emergencies`, `admins`), RLS, `register_device` |
| 2 | [`daily_kind.sql`](daily_kind.sql) | Lets you publish **daily** cases |
| 3 | [`leaderboard.sql`](leaderboard.sql) | Global leaderboard (`submit_score`, `get_leaderboard`) |
| 4 | [`server_grading.sql`](server_grading.sql) | Answer-stripped feeds (`get_cases`/`get_emergencies`) + server grading (`grade_case`); **locks `content`/`emergencies` to anon** |
| 5 | [`profiles.sql`](profiles.sql) | Per-account cloud-synced game state (XP, coins, streak…) |
| 6 | [`leagues.sql`](leagues.sql) | Real weekly leagues, rooms of ≤30 (`report_league`, `get_league`) |

> ⚠️ Order matters: `server_grading.sql` removes the anon read policies, so it
> must run **after** `schema.sql`.

After running, the app can: sync stripped questions, grade on the server, save
per-account progress, and run real leagues.

## 2. Register yourself as admin

The admin app can only publish/broadcast if your auth user is in `public.admins`.

1. Sign in once (CortexAdmin → Cloud Sync, or the player app).
2. Supabase ▸ **Authentication ▸ Users** → copy your user's **UUID**.
3. Run, with your UUID:
   ```sql
   insert into public.admins (id) values ('<YOUR_ADMIN_UID>')
     on conflict (id) do nothing;
   select * from public.admins;   -- confirm it's listed
   ```

---

## 3. Sign-in providers (Authentication ▸ Sign In / Providers)

The player app is **account-first** — sign-in is required to play.

- **Email** — enable the Email provider. For the **6-digit code** (instead of a
  magic link): Authentication ▸ **Email Templates ▸ "Magic Link"** → set the body
  to use **`{{ .Token }}`** (requires custom SMTP — see step 4 below).
- **Google** — enable, paste your Google OAuth client id/secret.
- **Apple** — enable; the OAuth "Secret Key" is a JWT generated by
  [`../scripts/apple_client_secret.py`](../scripts/apple_client_secret.py)
  (env-driven; expires every 6 months — regenerate and update).
- **Redirect URL** — add `cortexauth://login-callback` under
  Authentication ▸ **URL Configuration ▸ Redirect URLs**.

---

## 4. Email sending (SMTP)

Editing the email template requires custom SMTP (the built-in sender is locked +
rate-limited). Authentication ▸ Emails ▸ **Set up SMTP**:

- **Gmail** (quick, testing): host `smtp.gmail.com`, port `465`, username =
  your Gmail, password = a **Google App Password** (needs 2-Step Verification).
- **Production**: Resend / Brevo / SendGrid with a verified sending domain.

Then set the **Magic Link** template body to include `{{ .Token }}` so the
6-digit code is emailed.

## 5. Emergency push (optional — for alerts when the app is closed)

In-app emergency cards + local notifications already work once the player has
opened the app. To push to users who **haven't** opened it, deploy the server
sender:

1. **Deploy the function:**
   ```bash
   supabase functions deploy send-emergency
   ```
2. **Set its secrets** (APNs — never commit these):
   ```bash
   supabase secrets set APNS_KEY_P8="$(cat AuthKey_XXXX.p8)" \
     APNS_KEY_ID=XXXXXXXXXX APNS_TEAM_ID=XXXXXXXXXX \
     APNS_BUNDLE_ID=com.docriddles.cortex APNS_SANDBOX=true
   ```
3. **Schedule it every minute** — edit [`cron.sql`](cron.sql), paste your
   **`service_role` key** (Supabase ▸ Settings ▸ API) in place of
   `<SERVICE_ROLE_KEY>`, and run it. **Do not commit the real key.**
